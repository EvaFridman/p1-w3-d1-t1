# Задача 1 — одна таблица: типы и ограничения

Первый заход в SQL — руками. Проектируешь одну таблицу под каталог фильмов, подбираешь каждому полю правильный тип и ограничение, потом накатываешь и гоняешь полный CRUD. Всё сдаётся упорядоченными SQL-константами (см. «Что сдать»).

## Где работаешь

- **База** создаётся в терминале PostgreSQL (`psql`): команда `createDBSQLScript` выполняется там.
- **Всё остальное** — миграция (создание таблицы), сиды, запросы — в SQL-редакторе DBeaver, подключённом к созданной базе.

Порядок: подними Postgres → в `psql` создай базу → в DBeaver подключись к ней → выполняй остальные скрипты по очереди.

## Спроектируй таблицу

Таблица `movies` — каталог фильмов. Продумай, какой тип и какие ограничения нужны каждому полю, опираясь на разобранные сегодня типы:

- уникальный идентификатор строки;
- название — обязательное, короткая строка;
- режиссёр — короткая строка, может отсутствовать;
- год выпуска — целое; отрицательного или «до кино» быть не может (год не раньше 1888);
- рейтинг — дробное с одним знаком после запятой, в диапазоне от 0 до 10 (точная дробь, не с округлением);
- жанры — несколько значений одного типа в одном поле;
- вышел ли в прокат — флаг со значением по умолчанию;
- когда добавлен в каталог — момент времени, однозначный в любом часовом поясе, по умолчанию текущий.

Сам реши, где нужны `NOT NULL`, `UNIQUE`, `DEFAULT`, `CHECK`, какой тип идентификатора (`SERIAL` или `UUID`), где `DECIMAL`, а где нельзя `REAL`. Обоснование выбора типов — часть задачи.

Памятка по `CHECK` (сегодня на слайде её не было, вот форма): ограничение-проверка пишется прямо в колонке или в конце таблицы, например `rating DECIMAL(3,1) CHECK (rating >= 0 AND rating <= 10)`.

## CRUD-релизы

Полный набор операций над таблицей, каждая — отдельным запросом:

1. вставка нескольких фильмов (сид);
2. выбрать все фильмы;
3. выбрать один по идентификатору;
4. выбрать по условию — только вышедшие в прокат (`WHERE`);
5. обновить рейтинг конкретного фильма по идентификатору;
6. удалить фильм по идентификатору.

## Входные данные

Фильмы для сида — вставь именно эти строки:

```js
const seed = [
  { title: 'Прибытие поезда',   director: 'Люмьеры',      year: 1896, rating: 7.5, genres: ['документальный'],        is_released: true },

];
```

## Ожидаемый результат

В `psql` создаётся база, DBeaver к ней подключается. Скрипт создания таблицы отрабатывает без ошибок, и в структуре таблицы видно осмысленные типы: рейтинг и год — числовые, момент добавления — `TIMESTAMPTZ` с дефолтом, жанры — массив, флаг проката — `BOOLEAN` с дефолтом. Сид вставляет три фильма. Выбор всех возвращает три строки; выбор по идентификатору — одну; выбор вышедших в прокат отсекает «Дюну». Обновление меняет рейтинг ровно одного фильма, удаление убирает ровно одну строку — потому что в обоих есть `WHERE` по идентификатору. Ограничения работают: попытка вставить фильм с рейтингом 11 или годом 1500 отклоняется базой из-за `CHECK`, вставка второго фильма с тем же идентификатором — из-за первичного ключа. В сдаче каждый шаг — отдельная именованная константа, порядок выполнения читается сверху вниз.
